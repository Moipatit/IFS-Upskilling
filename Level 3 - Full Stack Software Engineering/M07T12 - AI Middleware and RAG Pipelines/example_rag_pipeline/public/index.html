How the Retrieval Pipeline Works

      

        This example begins by loading a local JSON knowledge base. The knowledge base contains
        short course records with details such as title, category, difficulty, duration, summary,
        and skills covered.
      

      

        The pipeline then divides each course into smaller chunks. Chunking is useful because a
        retrieval system should search focused pieces of information rather than large documents
        that may contain unrelated details.
      

      

        When the user asks a question, the retriever compares the question with each chunk using
        a simple keyword scoring strategy. The highest-scoring chunks are selected as the most
        relevant context.
      

      

        The prompt builder combines the retrieved chunks with the user's question. This creates
        an augmented prompt, which gives a language model supporting information before it
        generates a response.
      

      

        This project uses a mock language model instead of a live AI API. This allows you to
        understand the structure of a RAG pipeline without needing an API key or paid service.
        In a production application, the mock response function would be replaced with a call
        to a real language model.
