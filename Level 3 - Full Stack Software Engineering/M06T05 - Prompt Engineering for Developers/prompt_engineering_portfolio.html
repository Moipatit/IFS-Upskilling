Prompt Analysis

Prompt engineering is the process of creating effective instructions that help to guide an AI system towards producing useful and consistent outputs. AI models are perfectly capable of doing many things but the quality of their output is heavily influenced by the quality of the instructions that they receive.

Many people assume that prompt engineering is simply about asking the AI system questions. But the reality is that effective prompt engineering is much closer to writing technical requirements than having a casual conversion.

Developers use AI systems to do many things like code generation, explaining unfamiliar systems, creating documentation and troubleshooting technical problems. Using AI to perform all of these tasks helps to save significant amounts of times when done effectively. Developers who understand how to communicate effectively with AI systems are able to get much better solutions quicker while still maintaining great control over the development process.

One of the biggest misconceptions about prompt engineering is that the prompt needs to be perfectly written on the first try. Effective prompting is often an iterative process. Developers rarely get the exact output they need from the first prompt, instead they gradually improve the prompt based on the response that they receive. This process resembles software development very closely. Developers write code, test the results, identify issues and improve the solution through multiple iterations. Prompt engineering is less about writing perfect prompts and more about learning how to improve prompts systematically.

Code Generation Prompt

  1. "Generate a student dashboard for the SkillTrack platform"
  2. This prompt is weak because it lacks a lot of detail, this will result in the AI system making assumptions
  3. "Generate an accessible student dashboard using HTML, CSS and JavaScript. Include responsive styling for mobile devices, semantic HTML elements and appropriate error messages. Return the complete code with comments.
  4. This prompt is better because it has a better context, better constraint and better output requirements. The AI will be able to create a more useful and reliable response instead of making assumptions.

Debugging Prompt

  1. Fix my buggy code
  2. The following JavaScript code throws a Type error. Explain what causes the error, identify the problematic line, and provide a corrected solution. Also explain how the fix works.
  3. The second prompt is better because it provided context and expectations. The AI is able to understand the task and it can focus on identifying the root cause of the issue.

Documentation Prompt

Create a developer documentation for the search for courses by keyword feature. Include a description of its purpose, request parameters, example requests and example responses and possible error codes. Write for Professional developers.

The objective described what I wanted the AI system to accomplish. The context provided background information. The audience is included to ensure that the AI system will produce a document using the appropriate language.

Testing Prompt

Generate ten test cases for a user registration form. Include positive test cases, negative test cases, edge cases, validation scenarios and expected outcomes. Assume the form contains fields for full name, email address, password and password confirmation.

This prompt encourages broader test coverage and provides a clearer understanding od the requirements.

Prompt Refinement Challenge

Revision 1

Build a dashboard for a personal task management application. The dashboard should allow users to view and manage their daily tasks, monitor their progress, and organize their workload.

What was improved:

  • Added context by specifying that the dashboard is for a task management application.
  • Defined the main objective as helping users manage tasks and monitor progress.
  • Identified the primary functionality of the dashboard.

Providing context and objectives helps the AI understand what the dashboard is intended to accomplish. This reduces ambiguity and allows it to generate a more relevant solution.

Revision 2

Build a dashboard for a personal task management application using HTML, CSS, and JavaScript. The dashboard should allow users to view and manage daily tasks, monitor progress, and organize their workload. Include a summary of total tasks, completed tasks, pending tasks, and overdue tasks. Add a task list with task names, due dates, and completion statuses. Include a progress indicator and a simple navigation menu. Keep the design clean, responsive, and user-friendly. Use simple styling and avoid unnecessary animations or complex functionality.

What was improved:

  • Specified the technologies to use: HTML, CSS, and JavaScript.
  • Added concrete dashboard features and components.
  • Introduced design requirements such as responsiveness and simplicity.
  • Defined constraints to prevent unnecessary complexity.

The additional requirements give the AI clear instructions about the dashboard's functionality, technology stack, and appearance. This makes the generated output more predictable and reduces the likelihood of missing important features or introducing unnecessary complexity.

Revision 3

Objective

Build a functional, responsive dashboard for a personal task management application that allows users to manage their daily workload and track task completion.

Context

The dashboard is intended for individuals who want a simple and organized way to monitor their tasks, deadlines, and productivity.

Function Requirements

  • Display the total number of tasks, completed tasks, pending tasks, and overdue tasks.
  • Show a task list containing task names, due dates, and completion statuses.
  • Allow users to mark tasks as completed.
  • Include a progress indicator showing the percentage of completed tasks.
  • Provide a navigation menu with Dashboard, Tasks, and Settings sections.

Design requirements

  • Use HTML, CSS, and vanilla JavaScript.
  • Create a clean, modern, and minimalist interface.
  • Use a consistent color scheme, readable typography, and clear visual hierarchy.
  • Keep the styling simple and avoid unnecessary animations or complex visual effects

Constraints

  • Do not use external frameworks or libraries.
  • Keep the HTML, CSS, and JavaScript in separate files.
  • Use meaningful variable names and maintain readable, well-organized code.
  • Ensure the dashboard works without requiring a backend or database.

Output Requirements

  1. Provide the complete HTML, CSS, and JavaScript code.
  2. Explain the purpose of each file.
  3. Include instructions for running the dashboard locally.
  4. Ensure all specified features are functional and that the implementation follows the requirements.
